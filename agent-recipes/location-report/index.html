Location intelligence report (PDF) in fixed sections

Can an AI agent add data layers to a map and give me a PDF report about a place, with its own analysis and links back to the map?

Yes. The report has fixed sections. The app writes the ones that come from the map: the location, the features and attributes of every visible layer at the place, the sources, and a map snapshot linking to the whole map. The agent writes the ones that need reading the data together and general knowledge: summary, inferences (each with its basis and confidence), geographic context, limitations and next steps. A map-v1 link carries them in "report" and the viewer downloads the PDF from Intelligence; in a running page reports.location() returns the file.

Machine-readable recipeAll recipes

Ask for it like this

  • “Make a report about this location from these layers”
  • “Give me a PDF on what the data says about this address”
  • “Add flood and population layers and write up this site”
  • “Generate a location intelligence report for these coordinates”

Inputs

Accepts: A place (coordinates or an address you geocode), One or more public layers to combine, A map-v1 link. Engines: maplibre, arcgis.

  • at: The place: [longitude, latitude].
  • layers: The data layers whose features at the place the report reads.

Optional:

  • sections: Authored sections: summary, observations, inferences [{ statement, basis, confidence }], context, limitations, nextSteps. Location, sources and the map are written by the app.
  • title: The report title; the address by default.
  • author: Who wrote the analysis, shown as "Analysis by …".

Steps

Discover → inspect → plan → validate → execute → verify → share. Each step names where it runs; none is a hosted REST endpoint.

  1. discover: Read llms.txt, this recipe and api/capabilities.json; note the engine and execution environment you actually have. (Declarative URL; https://gismap.online/llms.txt, https://gismap.online/api/capabilities.json, https://gismap.online/api/manifest.json)
  2. inspect: Read the source metadata: geometry type, field names and types, spatial reference, extent, sentinels and query support. Query real values before filtering; never invent fields. (Declarative URL, Standalone JavaScript, In-browser API; <layer URL>?f=pjson, sources.inspect, sources.detectSentinels, layers.metadata)
  3. plan: Choose layers that answer the question together, and read their values at the place (query the layer with the point and inSR=4326) before writing. Decide what each layer measures from its field names and metadata. (Standalone JavaScript; <layer URL>/query?geometry=<lon>,<lat>&geometryType=esriGeometryPoint&inSR=4326&outFields=*&f=json, reports.sections)
  4. plan: Write the authored sections in the report's fixed order. Quote layer names and exact values; give each inference a basis and a confidence; keep general knowledge in Geographic context and out of the data sections; no chat or offers. (Standalone JavaScript; reports.sections, reports.prompt)
  5. validate: Add "report": { "type": "location", "at": [lon, lat], "sections": {…} } to the map-v1 spec and validate it; sections the app writes, unknown sections and bad confidences are reported. (Standalone JavaScript, In-browser API; mapSpec.validate, reports.validate)
  6. execute: Return the #map=json: link: it opens the map, inspects the place and offers the report in Intelligence. In a running page, reports.location({ at, report }) returns { file, report, issues, links } (or { ai: true } to have the configured AI write the sections). (Declarative URL, In-browser API; https://gismap.online/schemas/map-v1.schema.json, mapSpec.createLink, reports.location)
  7. verify: Open the link, wait for the Location report card in Intelligence, download the PDF and check the sections, the attribute values at the place and that the map link opens the same map. (In-browser API; reports.location)
  8. share: Return the link (and the PDF when you made it in a page). Say which sections are inference. (Declarative URL; mapSpec.createLink)

Result

map-v1 with layers and a "report" { type: "location", at, title, author, sections }. Schema: /schemas/map-v1.schema.json.

  • Map link that offers the report · Declarative URL
  • Location Intelligence Report (PDF) · In-browser API · static. Sections in order: Summary, Location, What the map data shows, Inferences from the layers together, Geographic context, Limitations, Suggested next steps, Sources, Map.

Verify before reporting success

  • The place is inside the layers' extent
  • Every value quoted in the authored sections matches the attributes the report lists
  • Each inference names its basis layers and a confidence
  • The map link in the PDF opens the same layers

Report prepared, validated, loaded, rendered and verified separately, and partial or failed when they apply. A generated link alone is only prepared.

Limitations

  • Only visible layers with features at the place are read; nothing is fetched beyond the map.
  • Authored sections are the agent's text: the app checks their shape, not their truth.
  • The PDF is made in the viewer's browser; no server stores it.

If something goes wrong

  • "report.at" issue: give [longitude, latitude] in degrees.
  • No features found: check the layer is visible and the place is inside it, or move the place.
  • A section was ignored: location, sources and map are the app's; write the others.
