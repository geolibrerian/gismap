LiDAR point clouds and 3D models (utility and vegetation data)

Can an AI agent put a LiDAR point cloud or a CAD model on a shareable 3D map?

Yes, on the MapLibre engine. A pointcloud layer reads LAS or LAZ (with its CRS) or XYZ text; a model layer reads glTF/GLB, OBJ or PLY placed at an anchor or from projected coordinates. Both draw with three.js on the map and travel in a #map=json: link, colored by RGB, ASPRS class, elevation or intensity, with a class filter for wires, towers and vegetation.

Machine-readable recipeAll recipes

Ask for it like this

  • “Show this LiDAR LAZ file on a map”
  • “Show only vegetation and conductor wires from this point cloud”
  • “Place this glTF transmission tower model at these coordinates”
  • “Put the CAD model of this substation on the map in 3D”

Inputs

Accepts: LAS 1.0–1.4 (point formats 0–10), LAZ (LASzip), XYZ / PTS text, glTF / GLB, OBJ, PLY. Engines: maplibre.

  • source: HTTPS URL of the file (the host must allow browser access, CORS), or a local file added in the app.

Optional:

  • crs: EPSG:<code>, proj4 or WKT; needed when the file carries none (XYZ, some LAS, CAD in projected coordinates).
  • classes: ASPRS classes to show, such as [3, 4, 5] vegetation, [13, 14] wires, [15] towers.
  • colorBy: auto, rgb, classification, elevation or intensity.
  • anchor: Model placement [lon, lat, altitude]; heading, scale and upAxis adjust it.
  • heightReference: ground (default, set on the terrain) or absolute (surveyed elevations).
  • animate: { type: "reveal" } shows points from low to high on the shared clock.

Steps

Discover → inspect → plan → validate → execute → verify → share. Each step names where it runs; none is a hosted REST endpoint.

  1. discover: Read llms.txt, this recipe and api/capabilities.json; note the engine and execution environment you actually have. (Declarative URL; https://gismap.online/llms.txt, https://gismap.online/api/capabilities.json, https://gismap.online/api/manifest.json)
  2. inspect: Check the file type, size and that its host allows browser access. For LAS/LAZ the header gives the point count and usually the CRS; ask for the CRS when it is missing rather than guessing. (Declarative URL, Standalone JavaScript; pointcloud-las.js#readLasHeader, pointcloud-las.js#lasCrs)
  3. plan: Choose colorBy and classes for the question (vegetation encroachment: classes 3–5 with 13–14; structures: 6, 15), a point size, and for models an anchor or the CRS of their coordinates. (Declarative URL; https://gismap.online/schemas/map-v1.schema.json)
  4. validate: Validate the spec; bad scene3d options are reported and ignored. (Standalone JavaScript, In-browser API; mapSpec.validate)
  5. execute: Write #map=json: with layers [{ url, type: "pointcloud" | "model", scene3d: {...} }], or call layers.add(url, { type, scene3d }) in an open page. (Declarative URL, In-browser API; mapSpec.createLink, layers.add)
  6. verify: Open the link on the MapLibre engine: the legend reports points shown of total, CRS and colour mode; tilt the map to see heights. (In-browser API; layers.list, mapSpec.fromCurrent)
  7. share: Return the link. Local files need a project package (.gisx); links only reference public URLs. (Declarative URL; mapSpec.createLink)

Result

map-v1 with pointcloud or model layers and their scene3d options. Schema: /schemas/map-v1.schema.json.

  • Interactive 3D map link · Declarative URL
  • Project with local LiDAR or CAD files (.gisx) · Outside GISMap. Made in the app; local files never go into links.

Verify before reporting success

  • Points or model visible where expected on the basemap
  • Legend: points shown of total, CRS, colour mode
  • Class filter and colours as requested
  • Heights plausible when tilted

Report prepared, validated, loaded, rendered and verified separately, and partial or failed when they apply. A generated link alone is only prepared.

Limitations

  • MapLibre engine only, flat (Mercator) map; the globe and the ArcGIS engine do not draw these layers.
  • Whole files load into the browser: large clouds are thinned to maxPoints (default 1.5 million). Streaming formats (COPC, EPT, 3D Tiles) are not supported yet.
  • No point picking, clearance measurement or IFC/DWG/DXF yet; convert CAD to glTF.
  • LAZ decoding loads laz-perf (WebAssembly) and reprojection loads proj4; unknown EPSG codes are looked up on epsg.io.

If something goes wrong

  • "does not say which coordinate system": add scene3d.crs.
  • Points in the wrong place: check the CRS and its units (US survey feet vs metres).
  • Nothing visible: open with ?engine=maplibre and switch off the globe.

Examples

Example · rendered · checked 2026-10-21

Autzen Stadium LiDAR (true colour)

Prompt: “Show this LAS file on a 3D map: https://raw.githubusercontent.com/PDAL/PDAL/master/test/data/las/autzen_trim.las”

Data: PDAL sample LiDAR: Autzen Stadium, Eugene, Oregon (LAS 1.2, RGB)

Open the result

map-v1 JSON
{
  "version": 1,
  "title": "Autzen Stadium LiDAR",
  "basemap": "gray-vector",
  "legend": true,
  "layers": [
    {
      "url": "https://raw.githubusercontent.com/PDAL/PDAL/master/test/data/las/autzen_trim.las",
      "type": "pointcloud",
      "title": "Autzen Stadium LiDAR (PDAL sample)",
      "scene3d": {
        "colorBy": "rgb",
        "pointSize": 2
      }
    }
  ]
}

What was checked:

  • Opened headless from this branch (local server): 110,000 points reprojected from the file's WKT (Oregon Lambert, international feet) to Eugene, Oregon; true-colour trees and ground visible when tilted (screenshot inspected).
  • Placed on the terrain at the cloud's ground level.
Example · loaded · checked 2026-10-21

Ground returns only, revealed by height

Prompt: “Show only the ground points, coloured by elevation, and animate them.”

Data: PDAL sample LiDAR: Autzen Stadium, Eugene, Oregon (LAS 1.2, RGB)

Open the result

map-v1 JSON
{
  "version": 1,
  "title": "Autzen ground surface",
  "basemap": "gray-vector",
  "legend": true,
  "layers": [
    {
      "url": "https://raw.githubusercontent.com/PDAL/PDAL/master/test/data/las/autzen_trim.las",
      "type": "pointcloud",
      "title": "Ground returns (class 2)",
      "scene3d": {
        "classes": [
          2
        ],
        "colorBy": "elevation",
        "pointSize": 3,
        "animate": {
          "type": "reveal",
          "durationMs": 6000,
          "loop": true
        }
      }
    }
  ]
}

What was checked:

  • Loaded through layers.add with classes [2] and the reveal animation running on the shared clock (mid-reveal screenshot).
  • This sample has only unclassified and ground classes; vegetation and wire classes need a classified utility survey.
