Numeric or fixed-height 3D extrusion

Can an AI agent make a 3D map where each area's height shows a number?

Yes. The agent checks that the layer has polygons and a numeric field, then writes a map-v1 spec whose ArcGIS renderer extrudes each polygon by $feature["FIELD"] × a multiplier (or a fixed height), with a tilted camera. The link reopens the same 3D view.

Machine-readable recipeAll recipes

Ask for it like this

  • “Make a 3D map of grape production in California”
  • “Make the county heights represent acreage”
  • “Extrude these buildings by height”

Inputs

Accepts: Polygon FeatureServer layer, Polygon GeoJSON. Engines: maplibre, arcgis.

  • source: A polygon layer.
  • height: A numeric field with a multiplier, or a fixed height in meters.

Optional:

  • where: Filter.
  • color: Uniform, categories or class breaks.
  • camera: Tilt 45–65° and a heading.
  • basemap: A *-3d basemap.

Steps

Discover → inspect → plan → validate → execute → verify → share. Each step names where it runs; none is a hosted REST endpoint.

  1. discover: Read llms.txt, this recipe and api/capabilities.json; note the engine and execution environment you actually have. (Declarative URL; https://gismap.online/llms.txt, https://gismap.online/api/capabilities.json, https://gismap.online/api/manifest.json)
  2. inspect: Read the source metadata: geometry type, field names and types, spatial reference, extent, sentinels and query support. Query real values before filtering; never invent fields. (Declarative URL, Standalone JavaScript, In-browser API; <layer URL>?f=pjson, sources.inspect, sources.detectSentinels, layers.metadata)
  3. plan: Confirm polygon geometry and a numeric field; check nulls, negatives, sentinels and outliers. Source units are not meters: pick a multiplier so the tallest feature is readable, and say so. (Standalone JavaScript; sources.inspect, renderers.describeValues)
  4. validate: Validate the spec; an unsupported extrusion expression is reported, not ignored. (Standalone JavaScript, In-browser API; mapSpec.validate)
  5. execute: Use renderer { type: "arcgis", json } with PolygonSymbol3D Extrude symbols and visualVariables [{ type: "sizeInfo", valueExpression: '$feature["FIELD"] * k' }] (or a fixed Extrude size), plus a camera with tilt. (Declarative URL, Standalone JavaScript; https://gismap.online/schemas/map-v1.schema.json, mapSpec.createLink)
  6. verify: Open the link and confirm the extrusion is drawn (MapLibre fill-extrusion or ArcGIS SceneView), the colors and the tilted camera. (In-browser API; layers.list, mapSpec.fromCurrent)
  7. share: Return the link; a Smart Map PNG keeps a picture with the project. (Declarative URL, In-browser API; mapSpec.createLink, smartImages.downloadCurrent)

Result

map-v1 with an ArcGIS renderer using Extrude symbol layers and a sizeInfo expression, and a tilted camera. Schema: /schemas/map-v1.schema.json.

  • Interactive 3D map link · Declarative URL
  • Smart Map PNG · In-browser API · static

Verify before reporting success

  • Polygon geometry confirmed
  • Height = field × multiplier (or fixed) on the drawn features
  • Colors match the legend
  • Camera tilted
  • Settings survive the share link

Report prepared, validated, loaded, rendered and verified separately, and partial or failed when they apply. A generated link alone is only prepared.

Limitations

  • MapLibre supports only $feature["FIELD"] * number expressions; other Arcade is refused with an error.
  • Heights are display meters, not the data's units; label the multiplier.
  • Points become columns only in some engines; polygon extrusion is the portable case.

If something goes wrong

  • If the extrusion is refused, simplify the expression to field × number.
  • If tall outliers hide the rest, lower the multiplier or filter outliers and say so.

Prompt: “Use county grape production, filter to California counties over 1,000 acres, extrude by acres × 0.01 with a purple ramp, tilt the camera, and give me a link.”

Data: USDA Census of Agriculture 2022 grape production (Esri)
