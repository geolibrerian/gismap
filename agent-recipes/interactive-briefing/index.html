Interactive geographic briefing

Can an AI agent build a slide briefing with one map slide per area and context from another layer?

Yes. A chatbot can write the whole briefing into one link: a map-v1 JSON with a briefing-v1 document in its briefing property, after #map=json:. The link opens presenting, as a desktop deck or a mobile swipe feed. In an open GISMap page, agents can also build, generate and export briefings through the in-page API, including relations to a context layer.

Machine-readable recipeAll recipes

Ask for it like this

  • “Create slides about these districts”
  • “Build an interactive crime briefing for Philadelphia”
  • “Make a presentation with one slide per county”

Inputs

Accepts: ArcGIS FeatureServer polygon layer, Supporting point or polygon layer. Engines: maplibre, arcgis.

  • primaryLayer: The layer whose features become slides.
  • selection: Feature IDs, a filter, or 'all', plus the slide order.

Optional:

  • contextLayer: A second layer shown and related per slide (spatialRel, distance).
  • narrative: Titles and text grounded in inspected data.
  • skin: Presentation look.
  • template: filter-series, timeline, grid-atlas or spatial-3d-chart for data-driven slides.

Steps

Discover → inspect → plan → validate → execute → verify → share. Each step names where it runs; none is a hosted REST endpoint.

  1. discover: Read llms.txt, this recipe and api/capabilities.json; note the engine and execution environment you actually have. (Declarative URL; https://gismap.online/llms.txt, https://gismap.online/api/capabilities.json, https://gismap.online/api/manifest.json)
  2. inspect: Read the source metadata: geometry type, field names and types, spatial reference, extent, sentinels and query support. Query real values before filtering; never invent fields. (Declarative URL, Standalone JavaScript, In-browser API; <layer URL>?f=pjson, sources.inspect, sources.detectSentinels, layers.metadata)
  3. plan: Pick stable feature IDs and the slide order. For context layers, decide the spatial relationship; an overlay alone is not evidence that points fall inside a polygon. (In-browser API; https://gismap.online/schemas/briefing-v1.schema.json, briefing.create, briefing.createSlide)
  4. validate: Validate the document statically before loading it. (Standalone JavaScript, In-browser API; briefing.validate, briefing.migrate)
  5. execute: Without code: put the briefing in map-v1 ("briefing": { layerId, selection, slides }) and write a #map=json: link; feature slides use the layer's OBJECTID as featureId. In an open page: load or generate the briefing. Slide layers with a relation query the context layer's service per slide, so counts come from the service, not from the drawing. (Declarative URL, In-browser API; briefing.load, briefing.generate, briefing.generateTemplate, briefing.addSlide, briefing.updateSlide)
  6. verify: Step through every slide on desktop and in a narrow (mobile) viewport: selected feature, highlight, camera, context layer, narrative numbers. State whether counts are complete, filtered or sampled. (In-browser API; briefing.get, describe)
  7. share: Create the link, then reopen it. Optional PDF handout and QR card. (In-browser API; briefing.createLink, briefing.exportPdf, briefing.exportQrCard, briefing.exportGmo)

Result

A briefing-v1 document: layerId, selection, ordered slides (template, camera, blocks, layers with relations, optional dataView/timeline/spatialChart), shared with the map's layers, styles and skin. Schema: /schemas/briefing-v1.schema.json.

  • Interactive briefing link (#briefing=) · In-browser API
  • Desktop deck and mobile swipe feed · Declarative URL. The same document; the layout follows the screen.
  • PDF handout · In-browser API · static
  • QR card (PNG) · In-browser API · static
  • Project file (.gis) · In-browser API

Verify before reporting success

  • Slide count matches the request
  • Each slide frames and highlights the intended feature
  • Context layer loaded and related by a real spatial query
  • Narrative numbers match queried values
  • Desktop and mobile navigation work
  • The shared link reopens to the same slides

Report prepared, validated, loaded, rendered and verified separately, and partial or failed when they apply. A generated link alone is only prepared.

Limitations

  • Readable #map=json: links hold 8,192 characters, enough for roughly ten short slides; longer briefings need the in-page API (briefing.createLink) or a hosted ?briefing= file.
  • Links hold at most 60 slides and must fit the URL budget; large documents use ?briefing=<hosted JSON>.
  • Data-driven templates sample at most 500 features (generateTemplate coverage is 'unknown').

If something goes wrong

  • If a relation query fails, the slide notes it; show both layers and say the analysis is incomplete.
  • If the link is too long, host the JSON and use ?briefing=<URL>, or export a .gis project.
