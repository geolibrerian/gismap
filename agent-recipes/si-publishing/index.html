Publish a Brief from GISMap SI with AI Map (GISMap SI alpha)

Can an AI agent help turn data stored in GISMap SI into a published, verified Brief?

Partly, by design. An agent can hand the person a GISMap SI draft: the /m/<id>?app=ai-map link that GISMap SI returns when it creates one. The person signs in to GISMap SI, builds the Brief with AI Map and presses Publish; GISMap SI then verifies the share link. The agent never handles the person's GISMap SI connection, and nothing publishes without the person. Needs GISMap SI alpha access while its connection tokens and public links are off for everyone else.

Machine-readable recipeAll recipes

Ask for it like this

  • “Make a Brief from our inspections dataset in GISMap SI and publish it”
  • “Open this GISMap SI dataset in AI Map”
  • “Publish this GISMap SI map for the meeting, with the figures frozen”
  • “Check that the published Brief still works”

Inputs

Accepts: A dataset stored in GISMap SI with a public FeatureServer link, A GISMap SI draft (/m/<id>), A publication share link (/m/<id>?p=<publication>). Engines: maplibre, arcgis.

  • draft: The draft's editUrl from GISMap SI (https://gismap.online/m/<id>?app=ai-map), created by the person in Stored Intel or by an SI tool that already holds their session. It carries only the map's id: no token and no private dataset id.

Optional:

  • request: What the Brief should cover, in the person's words; AI Map reads it from the draft's context.
  • dataMode: live (figures recompute when the Brief plays) or pinned (figures frozen and shown as of the publishing date). The person chooses in the Publish panel.

Steps

Discover → inspect → plan → validate → execute → verify → share. Each step names where it runs; none is a hosted REST endpoint.

  1. discover: Read llms.txt, this recipe and api/capabilities.json; note the engine and execution environment you actually have. (Declarative URL; https://gismap.online/llms.txt, https://gismap.online/api/capabilities.json, https://gismap.online/api/manifest.json)
  2. plan: Confirm every dataset has a public FeatureServer link. GISMap SI refuses a draft otherwise (409 needs_public_link, with canPublish per dataset): tell the person that an owner or admin publishes the dataset in GISMap SI first. Never work around it. (Outside GISMap Online; https://gismap.online/discover/ai/publish-with-gismap-si/)
  3. execute: Give the person the draft's /m/<id>?app=ai-map link. They sign in to GISMap SI in the popup it offers; the connection stays in their browser tab. Never ask for, copy or put a GISMap SI token in a link, file or message. (Declarative URL; https://gismap.online/m/<id>?app=ai-map)
  4. execute: Inside AI Map the assistant has the draft's GISMap SI context as reference data and the si_dataset_context, si_add_dataset and si_find_datasets tools; it builds the Brief with describe_layer, summarize_field and create_briefing and finishes with si_publish_preview, which only opens the Publish panel. (In-browser API; create_briefing, si_publish_preview)
  5. share: The person reviews the audience (anyone with the link), live or pinned, the layers and the figures, and presses Publish. The share link is /m/<id>?p=<publication>, opened in the viewer without signing in. (Declarative URL; https://gismap.online/m/<id>?p=<publication>)
  6. verify: Read the verification report shown in the Publish panel (or si_verify in AI Map): status passed, warning or failed, and each check's message as written. External layers are reported as not_checked. Report what was checked and what was not. (In-browser API; si_verify)

Result

A GISMap SI saved map of kind brief: map state plus briefing slides, with optional pinned figures on stat blocks; viewers read one published version. Schema: /schemas/map-v1.schema.json.

  • Editable draft for the workspace (/m/<id>) · Declarative URL. Members of the GISMap SI workspace only; needs sign-in.
  • Verified share link (/m/<id>?p=<publication>) · Declarative URL. Anyone with the link, once GISMap SI's public links are on.

Verify before reporting success

  • The draft opens in AI Map with the datasets on the map
  • Every slide field exists in the layer (describe_layer)
  • No invented figures: stat blocks or summarize_field only
  • The person pressed Publish; the report's status and each check message are passed on as written
  • The share link opens in the viewer without signing in

Report prepared, validated, loaded, rendered and verified separately, and partial or failed when they apply. A generated link alone is only prepared.

Limitations

  • GISMap SI alpha only: connection tokens and public share links are switched on for allowlisted people; everyone else gets the sign-in prompt or a not-found page.
  • The only audience is anyone with the link; team-only and named-viewer links come later.
  • Layers keep the data their FeatureServer links serve; a live publication recomputes figures but does not follow newer data yet.
  • No tool publishes: an agent can prepare and open the Publish panel, but the person presses Publish.
  • Maps and Briefs only; Tours and Cinematic animations are not published yet.

If something goes wrong

  • "Sign in to GISMap SI": the connection expired (after eight hours) or was revoked; the person signs in again.
  • "A newer version of this map exists" (409): someone else saved; reload the map before publishing.
  • Plan limit (402): the workspace has reached its maximum; the owner upgrades or deletes old maps in GISMap SI.
  • A dataset with no public link: an owner or admin publishes it in GISMap SI; others ask one.
  • Verification failed: read each failed check, fix that layer or field, save and publish again.
