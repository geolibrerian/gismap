# Local vector files and DuckDB

Data → Add KML / KMZ / zipped SHP / GeoJSON opens files locally in both MapLibre and ArcGIS. KML/KMZ and shapefiles are converted to GeoJSON using the same browser-side import path. A ZIP with multiple shapefiles creates a layer per shapefile. ZIPs need a `.prj` for every `.shp`; add the matching `.dbf` for attributes and `.cpg` for non-default encodings. KML styles, network links, overlays, 3D models, and KMZ embedded resources may not be preserved. KML service URLs remain unsupported in MapLibre.

Files are limited to 100 MB and archives to 250 MB uncompressed; large datasets can still exhaust browser memory. Parsing currently runs on the main thread. Use a smaller file when a device is slow or cannot load the archive. The original file is retained for project packages; export a project package to carry local assets. A plain project or share link cannot transfer local files, and the existing engine switch blocks when local layers cannot be preserved.

On a local vector layer, **Query in DuckDB** lazily registers a browser-session snapshot of up to 20,000 records and 32 MiB of serialized data, independently of active layer filters. GISMap reads local layers in bounded pages and identifies incomplete or unverified snapshots. Register multiple layers through their layer actions to use them together in the shared SQL workspace; their displayed dataset names are SQL relation names. The snapshot is not live: layer edits after registration are not reflected until the DuckDB session is restarted. Removing a layer releases its snapshot. Attributes remain local and geometry is available as GeoJSON text in `__gismap_geometry`; spatial SQL requires a supported DuckDB spatial extension and explicit geometry conversion. Queries do not automatically update the source layer. Include `__gismap_geometry` in a result to enable **Add results to map**; this creates a local layer containing only the returned rows. Save a project package to retain it. Results may themselves be truncated by the workspace limit. DuckDB session data does not persist after reload.

## Analysis readiness (Phase 0)

Registered map layers have a session-only analysis descriptor containing the source format and location category, layer and relation identity, known fields, geometry field/encoding and observed types, CRS status, coverage scope and status, and snapshot/source freshness. No credentials or source URLs are stored in this descriptor. The SQL workspace displays a short readiness summary when a dataset is selected. A local snapshot's coverage is relative to the **loaded map layer**, not necessarily the original file; its count does not prove the original import retained every feature. Its requested CRS has not been independently validated. GeoParquet describes the source relation separately from the bounded map preview, and its declared CRS and geometry column come from the file metadata; the source is not version-pinned.

Changing or editing a layer does not automatically refresh its analytical snapshot. Removing a layer, clearing the map, or stopping DuckDB releases its map-owned relation. Registrations and descriptors are session-only and are not saved or shared. These descriptors are groundwork, not permission to treat unverified coordinates or partial coverage as a complete spatial analysis. No universal analysis builder or distance operations are implemented in this phase.
