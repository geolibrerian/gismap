# Local vector files and DuckDB

Data → Add KML / KMZ / zipped SHP / GeoJSON opens files locally in both MapLibre and ArcGIS. KML/KMZ and shapefiles are converted to GeoJSON using the same browser-side import path. A ZIP with multiple shapefiles creates a layer per shapefile. ZIPs need a `.prj` for every `.shp`; add the matching `.dbf` for attributes and `.cpg` for non-default encodings. KML styles, network links, overlays, 3D models, and KMZ embedded resources may not be preserved. KML service URLs remain unsupported in MapLibre.

Files are limited to 100 MB and archives to 250 MB uncompressed; large datasets can still exhaust browser memory. Parsing currently runs on the main thread. Use a smaller file when a device is slow or cannot load the archive. The original file is retained for project packages; export a project package to carry local assets. A plain project or share link cannot transfer local files, and the existing engine switch blocks when local layers cannot be preserved.

On a local vector layer, **Query in DuckDB** creates a browser-session snapshot of up to 5,000 records, independently of active layer filters. The workspace identifies incomplete or unverified snapshots. Attributes remain local and geometry is available as GeoJSON text in `__gismap_geometry`; spatial SQL requires a supported DuckDB spatial extension and explicit geometry conversion. Queries do not automatically update the source layer. Include `__gismap_geometry` in a result to enable **Add results to map**; this creates a local layer containing only the returned rows. Save a project package to retain it. Results may themselves be truncated by the workspace limit. DuckDB session data does not persist after reload.
