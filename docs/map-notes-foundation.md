# Map Notes foundation (in progress)

Map Notes are separate, project-owned records, not modifications to feature services. `schemas/map-note-v1.schema.json` describes the currently supported subset; `js/map-notes.js` validates records, limits untrusted input, and implements a registry over the existing project object. The normal project snapshot includes `notes`. Older projects without notes load with an empty array; invalid note data is rejected before changing the map. A saved project uses the existing project storage and export paths. This is browser-local, not collaboration or publication.

Only point, line, and polygon longitude/latitude anchors are accepted. Feature relationships contain dataset and feature IDs and remain independent of the referenced layer. Review status is separate from note status. Text is data, never rendered as HTML by this module. Attachments, unknown fields and future versions are rejected rather than silently lost. Import currently refuses duplicate IDs; response-bundle merge is not implemented.

The Map Notes tool supports creating and editing point-anchored notes from a clicked location, navigating to them, and importing or exporting bounded JSON bundles. The existing project save/export stores notes; unsaved projects must be saved explicitly, and saved projects must be reopened after a reload. Engine switching warns that notes are not carried through the reload.

This is **not yet the full MVP**: there is no map rendering, feature association UI, IndexedDB store, seamless engine-switch integration, CSV/Markdown/GeoJSON/QR export, undo, Observations mode, or agent access. Do not advertise these capabilities until implemented and tested. Public state and AI tools intentionally do not expose note content. A future UI must use text-safe DOM rendering and obtain explicit user approval for sharing or sending private contents to AI.

## Revised field-collection priority (in progress)

The field workflow is now the primary direction. The current incremental slice stores observation snapshots in IndexedDB before updating the existing project registry. A failed local transaction does not report success; concurrent edits to the same session from another tab are detected. The database reserves a separate attachment store, but accepting attachments is not implemented. A field session can be named and explicitly resumed into an empty project after a reload; the original project/feature references are retained. Sessions are local to the browser origin and device. Map-click and GPS positions are recorded with a coordinate source, observation time, revision, and GPS accuracy where available. The user must grant location permission, and HTTPS (or localhost) is required by browsers.

Notes JSON currently exports the existing note bundle, including field metadata, but **does not yet include session metadata**. The existing importer rejects duplicate IDs and limits files to 2 MB. Resume is explicit, not automatic, and does not restore the original map or project. Save a project separately if that context is needed. Browser storage can be evicted; request persistent storage and export backups. The application shell is not yet cached for offline launch, so do not assume GISMap can reopen without connectivity. GPS, actual offline use, and mobile behavior require further device testing.

Remaining phase 1: portable session bundles and deduplicating import, independent GPS and feature positions, feature association UX, map markers, session metadata and project restoration, service-worker/offline shell, and the basic PDF report with real QR/link portability. Multipart QR, richer reports, photos and packages remain phase 2. No claim is made that the revised phase 1 acceptance criteria are complete.
