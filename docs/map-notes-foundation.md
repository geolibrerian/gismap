# Map Notes foundation (in progress)

Map Notes are separate, project-owned records, not modifications to feature services. `schemas/map-note-v1.schema.json` describes the currently supported subset; `js/map-notes.js` validates records, limits untrusted input, and implements a registry over the existing project object. The normal project snapshot includes `notes`. Older projects without notes load with an empty array; invalid note data is rejected before changing the map. A saved project uses the existing project storage and export paths. This is browser-local, not collaboration or publication.

Only point, line, and polygon longitude/latitude anchors are accepted. Feature relationships contain dataset and feature IDs and remain independent of the referenced layer. Review status is separate from note status. Text is data, never rendered as HTML by this module. Attachments, unknown fields and future versions are rejected rather than silently lost. The legacy registry importer refuses duplicate IDs; portable field-session imports skip identical records and reject conflicting versions.

Map Notes mode opens in the workspace and supports creating and editing point-anchored observations from a clicked feature or location (and GPS on mobile), navigating to them, and importing or exporting bounded JSON bundles. Observations are stored in IndexedDB; field sessions can be explicitly resumed after reload, including into a project holding notes from that session. Project context still requires separate project saving. Engine switching warns that notes are not carried through the reload.

Point notes and the current draft have markers while the mode is open, in both engines. This is **not yet the full MVP**: there is no automatic feature relinking, seamless engine-switch integration, CSV/Markdown/GeoJSON/QR export, undo, Observations mode, or agent access. Do not advertise these capabilities until implemented and tested. Public state and AI tools intentionally do not expose note content. A future UI must use text-safe DOM rendering and obtain explicit user approval for sharing or sending private contents to AI.

## Revised field-collection priority (in progress)

The field workflow is now the primary direction. The current incremental slice stores observation snapshots in IndexedDB before updating the existing project registry. A failed local transaction does not report success; concurrent edits to the same session from another tab are detected. The database reserves a separate attachment store, but accepting attachments is not implemented. A field session can be named and explicitly resumed into an empty project or a project containing notes from the same session after a reload; matching records are merged without overwriting divergent versions, and project-only records are saved to IndexedDB before the project is changed; the original project/feature references are retained. Sessions are local to the browser origin and device. Map-click and GPS positions are recorded with a coordinate source, observation time, revision, and GPS accuracy where available. The user must grant location permission, and HTTPS (or localhost) is required by browsers.

Portable JSON exports the active session metadata and normalized observations, including existing feature references. Older notes-only bundles remain supported. Re-import skips identical observation IDs and rejects conflicting contents without overwriting records. A session bundle can be imported into an empty project or the same active session; importing it into a different nonempty session is intentionally blocked. The importer limits files to 32 MB and 5,000 observations. Resume is explicit, not automatic, and does not itself restore the original map or project. When the project already contains field-session notes, resume the corresponding saved session before editing or adding notes. Save a project separately if that context is needed. Browser storage can be evicted; request persistent storage and export backups. The application shell is not yet cached for offline launch, so do not assume GISMap can reopen without connectivity. GPS, actual offline use, and mobile behavior require further device testing.

Remaining phase 1: source geometry snapshots and automatic feature relinking, automatic project restoration and multi-session project merging, service-worker/offline shell, and the basic PDF report with real QR/link portability. Multipart QR, richer reports, photos and packages remain phase 2. No claim is made that the revised phase 1 acceptance criteria are complete.


## Feature-linked observations and collector GPS

An identified feature in Map Insight offers **Add observation**. Clicking the map in Map Notes mode also inspects the selected feature before allowing a save. The note keeps the map-clicked location, dataset reference and, when the source exposes one, its stable feature ID. A safe, credential-free HTTP(S) source URL and dataset title are preserved where available. Generated MapLibre `__OBJECTID` values are deliberately not treated as stable: such notes retain only a dataset reference. Local or credential-protected datasets may require manual reconnection; links do not automatically load or highlight their feature yet.

On mobile, **Record collector GPS** can add a separate position and reported accuracy without moving the observation's anchor. These coordinates, timestamp and feature references survive project snapshots and portable JSON. Browser location permission is required; actual GPS capture and offline/mobile device behavior have not yet been verified.

The Create PDF control is a disabled placeholder: report generation and portable QR/link support are not yet implemented. Desktop authoring does not request GPS.

## Portable single-observation links

A point observation's **Share link** action explicitly warns that its complete contents, coordinates, feature references and session metadata are visible to anyone with the link. Only after choosing Copy does the app place it on the clipboard. The fragment contains the same validated, versioned field-session bundle as JSON export, with exactly one observation; no server stores it. Links can still be exposed through browser history, clipboard history, screenshots or recipients, so they are not appropriate for secrets. Oversized observations are rejected without truncation; use JSON export instead.

Opening a link centers the map and previews the note without saving it. The recipient must explicitly import it; existing conflict checks apply. The link retains source references, but does not yet automatically load or highlight the source feature. This is a foundation for report links, not a PDF exporter or QR package. Non-point anchors, larger notes, multiple observations and multipart QR are not supported by this link format. Opening GISMap itself still requires the application to be available; offline launch is not yet implemented.
