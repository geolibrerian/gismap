# AI documentation delivery checks

The canonical documentation is `/llms.txt`; `/llms-full.txt` is its expanded reference. They contain Markdown but are served as `text/plain; charset=utf-8` for HTTP-reader compatibility. `/llm.txt` is a permanent compatibility redirect, not a second canonical document. As a fallback only, the current main-branch source is [available on GitHub](https://raw.githubusercontent.com/geolibrerian/gismap/main/llms.txt); it can differ from a preview or deployed version.

After publishing an isolated Cloudflare Pages preview, run:

```sh
node scripts/smoke-llms.mjs https://ACTUAL-DEPLOYMENT.pages.dev --match-local
```

The development preview workflow runs this against the URL returned by the deploy action. It checks both llms files, the skills HTML page, skill and recipe Markdown as UTF-8 plain text, the ZIP archive and its entries, the 301 alias, a real 404 and byte-for-byte equality with the artifact in the checkout. It logs cache and validation headers without enforcing a particular caching policy. A cache hit is not itself an error, but a stale type or body fails the check. Do not treat a passed preview as proof of production behavior; after an explicitly approved production deployment run the same command against `https://gismap.online` with the matching checkout. Check the printed cache status and investigate Cloudflare rules, Access challenges, redirects, CDN cache or Functions if delivery differs. Changes to Cloudflare configuration outside this repository cannot be verified from the source tree.

Before declaring external AI acceptance, use a fresh anonymous session with each client and record whether it retrieved and summarized each canonical URL without relying on a GitHub copy. A successful ordinary HTTP request alone is not that acceptance test. Next, independently test the supported map and briefing workflows, recording what each agent actually verified. Never put credentials or private data in test links.

## Skills delivery audit — 2026-10-20

Before this change, anonymous HTTP GET requests to production returned 200 without redirects for `/skills/`, `/skills/gismap/SKILL.md`, `/skills/gismap/references/agent-recipes.md`, `/llms.txt`, `/llms-full.txt`, and `/skills/gismap.zip`. The page was `text/html`; both Markdown files were `text/markdown`; both llms files were `text/plain; charset=utf-8`; the ZIP was `application/zip` and `unzip -t` reported no errors. Responses reported `Cache-Control: public, max-age=0, must-revalidate` and `CF-Cache-Status: MISS`. All but the HTML page had ETags; no Last-Modified or Expires headers appeared. No expiration or deprecation metadata was found in the checked-in skill. This establishes neither why a particular reader rejected llms.txt nor why Copilot said expired.

The static header rule now targets `/skills/*.md` (including nested references) as UTF-8 plain text, leaving Markdown contents, HTML, ZIP and cache policy unchanged. [Cloudflare Pages header rules](https://developers.cloudflare.com/pages/configuration/headers/) apply to static assets, not responses produced by Pages Functions. This checkout has no `functions/` directory or `_worker.js`, but dashboard-managed Workers, transforms, caching and security rules require inspection in the Cloudflare account and verification on the actual preview deployment. Two requests with crawler-like user-agent strings returned HTTP 200 for the skill page, but user-agent strings can be spoofed: this does not establish that verified Bing crawlers or Copilot are exempt from challenges. Check Cloudflare security events and verified-bot rules with account access.

After deploying to an isolated preview, run the command above and inspect all printed headers. After explicitly approved production deployment, repeat against production. Finally, in a fresh Microsoft Copilot conversation ask it to open `/skills/`, explain the six recipes and identify the map creation workflow. Record the exact response, client and date; a curl test, spoofed crawler user-agent or valid ZIP is not evidence of Copilot acceptance. If Copilot still reports expiration, request the exact message or screenshot and record it as a client-specific finding until independently established otherwise.
