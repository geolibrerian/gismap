AI map creation guide

Create and share interactive ArcGIS maps with AI

An AI assistant can describe a public ArcGIS feature layer, its style and map settings in a GISMap link. Open it in a browser and share it—no GISMap account, GISMap API key, coding or separate website is required for supported public data.

How do I turn a FeatureServer into a shareable map?

Ask an assistant to inspect the publisher’s layer metadata, select a suitable field and generate a map-v1 specification. URI-encode its JSON after https://gismap.online/#map=json:. Open the link in GISMap, verify the loaded layer and legend, then share the link. The app requests the source and basemap directly; the publishers must permit access.

Try this prompt

Copy this prompt into your AI assistant. It does not require connecting an AI provider to GISMap.

Use GISMap.online to make a shareable interactive choropleth from https://services.arcgis.com/P3ePLMYs2RVChkJx/ArcGIS/rest/services/Corn/FeatureServer/0. Inspect the layer metadata and the numeric field CORN_SALES_IN_DOLLARS. Exclude the publisher's -1 Not Disclosed code from the classes, use the greens ramp and gray-vector basemap, and produce a valid map-v1 JSON spec and URI-encoded #map=json: link. Follow https://gismap.online/llms.txt and the map schema. State what you actually verified; do not invent data.

Worked example: county corn sales

The public layer metadata identifies CORN_SALES_IN_DOLLARS and labels -1 as Not Disclosed. This example uses automatic classification, a green ramp and the gray-vector basemap. See the full example and its QR code.

{
  "version": 1,
  "basemap": "gray-vector",
  "layers": [
    {
      "url": "https://services.arcgis.com/P3ePLMYs2RVChkJx/ArcGIS/rest/services/Corn/FeatureServer/0",
      "renderer": {
        "type": "choropleth",
        "field": "CORN_SALES_IN_DOLLARS",
        "method": "auto",
        "ramp": "greens",
        "exclude": [
          -1
        ]
      }
    }
  ]
}

Validate and share

  1. Inspect source metadata, field types, terms and browser access; never put tokens or sensitive data in a URL.
  2. Compare the JSON with the map schema, renderer schema and URL parameter reference. Agent tools can validate the specification.
  3. Open the link in a browser, check the map, legend and data, and share the URL. Automatic breaks may change if the data changes; save the resolved classes for a consistent result.

Limits and alternatives

A link describes a map, not a copy of remote data. Publisher availability, CORS, access rules, basemap services, network access and a compatible browser matter. Private or local data may require separate access and are not embedded in the link. Long links can exceed QR or platform limits. The map specification and browser-independent utilities are distinct from in-page APIs, which require an active GISMap browser session; hosted authoring is not implied.

See the agent skill, AI documentation and more examples.

Privacy by design. GISMap runs in the browser. Remote services are requested from their publishers, and local files stay on the device unless you choose to export or share them elsewhere.
